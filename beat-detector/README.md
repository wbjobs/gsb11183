# 节拍检测器（BPM & Beat Visualizer）

纯前端本地音频节拍检测工具：选择本地音频文件后，在浏览器内完成 BPM 检测、
波形与节拍点可视化、播放/暂停、灵敏度调节和节拍时间点导出。
只做检测与可视化，不做混音、不做剪辑。

## 运行

需要通过 HTTP 服务访问（Web Worker 不能用 file:// 加载）：

```bash
cd beat-detector
python3 -m http.server 8000
# 打开 http://localhost:8000
```

可用 `test/demo-128bpm.wav`（128 BPM 合成示例）快速验证。

## 技术架构

- **Web Audio**：`decodeAudioData` 在低采样率（11025 Hz）AudioContext 中解码并
  混合为单声道 —— 100MB 文件解码后内存降低约 4 倍，避免崩溃；播放复用同一缓冲区。
- **Web Worker**（`js/beat-worker.js`）：频谱包络计算与 BPM 估计全部在后台线程执行，
  音频数据通过 Transferable ArrayBuffer 零拷贝传递，主线程不卡。
- **Canvas**：波形用 min/max 峰值列绘制，节拍点为竖线，播放头随 `requestAnimationFrame`
  移动；点击波形可跳转播放位置。
- **TypedArray**：全链路 `Float32Array`，无装箱开销。

## 检测算法（`js/beat-dsp.js`）

1. **起始包络**：512 点 FFT（自实现基-2）+ 对数谱通量（spectral flux），
   帧移 256（包络帧率约 43 fps）。
2. **自适应白化**：包络减去约 1s 滑动均值并除以滑动标准差，再平方做峰值强调 ——
   抑制平稳噪声底及其波动，突出真实瞬态（抗噪声干扰）。
3. **BPM 估计**：包络轻度平滑后做归一化自相关；候选峰做**分数 lag 精化**
   （线性插值，0.1 帧步长）；**谐波聚类**（2/3/4 倍关系）后用非对称速度先验
   （中心 120 BPM）仲裁半速/倍速误判。
4. **峰值拾取**：阈值 = 均值 + k×标准差，k 随灵敏度反向变化 ——
   灵敏度越高、阈值越低、节拍点越多（正相关）；最小间隔由 BPM 约束。
5. **无节拍提示**：自相关置信度 < 0.2 判定为无明显节拍（纯噪声、语音等），
   界面显示提示。

## 验收标准对应

| 标准 | 实现 |
| --- | --- |
| 100MB 音频不崩 | 低采样率解码 + 单声道 + Transferable 传输 |
| BPM 合理 | 自相关 + 分数 lag + 谐波聚类 + 速度先验 |
| 节拍点准确 | 谱通量包络峰值，测试验证 >90% 对齐 |
| 灵敏度正相关 | 阈值随灵敏度单调下降 |
| 无节拍提示 | 置信度阈值 + 界面提示 |
| 检测 < 5s | 10 分钟音频实测约 0.4s（Node） |
| 播放/暂停 | AudioBufferSourceNode + 偏移记录 |
| 可导出 | CSV（序号,秒）下载 |
| 主线程不卡 | 重计算全在 Worker，进度条反馈 |
